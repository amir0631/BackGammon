# Security review — 2026-09-29 (CLAUDE.md §17 step 18, §12.1)

Scope: backend (Django, Channels), Nginx config, Docker setup, environment handling. Frontends were
covered only where they reach the API (same-origin, CSP).

## Fixed in this change

| # | Severity | Finding | Fix |
|---|---|---|---|
| S-1 | Critical | With `PAYMENT_GATEWAY=sandbox` (the default until a PSP is chosen) and `payments.enabled` switched on in production, anyone could open the sandbox page for their own pending payment, press "Pay", and be credited coins without paying. | The sandbox gateway refuses to work when `APP_ENV=production`: checkout returns `PAYMENT_GATEWAY_UNAVAILABLE`, the sandbox page is 404, and verification can't run. Test: `test_sandbox_never_pays_in_production`. |
| S-2 | High | `JWT_SIGNING_KEY` and `ADMIN_SECRET_KEY` silently fell back to `DJANGO_SECRET_KEY`, and an empty value in `.env` would have signed tokens with an empty key. | Empty values fall back (dev only). A system check (`config/checks.py`, run by `manage.py migrate` before every deploy) refuses production unless the three keys are different random strings of 32+ characters, `DJANGO_DEBUG` is off, `URL_SCHEME` is `https`, and `SEED_ENCRYPTION_KEY` is set. |
| S-3 | Medium | Uvicorn accepted WebSocket frames up to its 16 MiB default; every client message is tiny. | `--ws-max-size 65536` in the backend image. |

## Checked and in order

- Passwords Argon2; OTP stored hashed, 2-minute validity, per-phone and per-IP limits; login lock after 5 failures.
- Access and refresh tokens in HttpOnly, Secure (with https), SameSite=Lax cookies; admin uses host-only cookies with other names and a different signing key; user tokens are refused by admin endpoints and vice versa.
- CSRF on cookie-authenticated writes; only the gateway callback and the (non-production) sandbox page are exempt.
- Client IP comes from `X-Real-IP`, which Nginx always overwrites with the connecting address, so a client can't spoof it through `X-Forwarded-For`.
- `/api/v1/admin/` is 404 on `m.`, `app.` and the root; admin endpoints also check host and the optional IP allowlist.
- WebSocket: auth within 5 s, 20 messages per second per connection, pydantic validation with `extra="forbid"`, spectator and admin sockets can't send game actions.
- Replay endpoints 403 for non-participants, every access logged.
- Phone numbers never in other users' payloads (tests assert `phone` absent).
- Web Push only POSTs to an allowlist of push-service hosts (no SSRF).
- `PATCH me` accepts only `lang`, `avatar` (validated against presets and owned items) and `prefs`.
- Security headers on every subdomain: CSP without third-party origins, `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`.
- Secrets are not committed (`.env`, `Arvan.txt`, keys in `.gitignore`).

## Open items for the server deploy

- TLS and HSTS (`max-age=31536000; includeSubDomains`) go in the server's TLS block with the wildcard certificate; this repo serves plain HTTP behind it. Not verifiable until `Arvan.txt` exists (§22.2).
- If a CDN or load balancer sits in front of Nginx, set `real_ip_header` and `set_real_ip_from` to its ranges so `X-Real-IP` is the player's address; otherwise every player shares the CDN's IP, which breaks per-IP rate limits and the §12.2 IP links.
- Set `ADMIN_IP_ALLOWLIST` to the office or VPN ranges.
- Keep `payments.enabled` off until the real PSP adapter is written and `PAYMENT_GATEWAY` names it.
